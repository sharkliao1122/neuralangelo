# 2. 結論摘要

目前道路模型仍保留 NVIDIA 官方 Neuralangelo 的主要架構：

- Hash-grid Neural SDF
- 數值法 SDF gradient
- IDR-style Neural RGB
- Background NeRF
- NeuS alpha conversion 與 alpha compositing
- Render、eikonal、curvature 三類 loss
- AdamW optimizer
- Warmup 與 two-step learning-rate scheduler
- Coarse-to-fine hash-grid activation

目前**沒有改寫**以下核心網路結構：

- SDF MLP 層數與 hidden dimension
- RGB MLP 層數與 hidden dimension
- BackgroundNeRF 層數與 hidden dimension

## 2.1 目前相對官方 Base 的主要差異

1. Appearance embedding：由關閉改為開啟。
2. Coarse-to-fine 初始 active level：由 4 改為 8。
3. Random rays：由 512 改為 256。
4. Learning rate：由 `1e-3` 改為 `1e-4`。
5. Curvature loss weight：由 `5e-4` 暫時改為 `0`。
6. 訓練解析度、資料載入方式與記錄週期有調整。
7. 新增 non-finite tracing 診斷功能。
8. 新增 ray / sphere 後向交點 bounds 修正。

> Appearance embedding 與 outdoor coarse-to-fine level 8 都是 NVIDIA 官方 `generate_config.py` 已支援的設定，不是自行設計的新網路結構。

## 4.5 Rendering 與取樣

| 項目 | NVIDIA 官方 Base | 目前道路模型 |
|---|---:|---:|
| Random rays / batch image | 512 | 256 |
| Object coarse samples | 64 | 64 |
| Fine samples / hierarchy | 16 | 16 |
| Hierarchy rounds | 4 | 4 |
| Object samples total | `64 + 16×4 = 128` | 128 |
| Background samples | 32 | 32 |
| Combined samples / ray | 160 | 160 |
| Stratified sampling | True | True |
| NeuS `s_var` init | 3.0 | 3.0 |
| Cosine anneal end | 0.1 | 0.1 |

### 差異與影響

- `rand_rays` 由 512 降為 256，以降低 Windows 單 GPU 的記憶體與單步運算成本。
- 每一步使用的 ray 較少，因此梯度抽樣變異可能較高。
- 此修改不屬於模型 layer 變更。
- Object 與 background 的 sample 數量與官方相同。
- `max_iter` 必須維持 500,000，因為：

```text
progress = current_iteration / max_iter
```

此值會控制 NeuS annealing。

# 5. Loss、Optimizer 與 Scheduler

| 項目 | NVIDIA 官方 Base | 目前道路測試 |
|---|---:|---:|
| Render loss | `L1 × 3` | 相同 |
| Render weight | 1.0 | 1.0 |
| Eikonal weight | 0.1 | 0.1 |
| Curvature weight | `5e-4` | `0.0` |
| Optimizer | AdamW | AdamW |
| Learning rate | `1e-3` | `1e-4` |
| Weight decay | `1e-2` | `1e-2` |
| Warmup end | 5000 | 5000 |
| LR steps | 300000、400000 | 相同 |
| Gamma | 10.0 | 10.0 |
| AMP | False | False |
| EMA | False | False |
| `max_iter` | 500000 | 500000 |

## 5.1 修改原因

- `learning_rate=1e-4`：NaN 調查期間使用的保守設定，不是 layer 架構修改。
- `curvature=0`：暫時隔離 render/background NaN 的診斷設定。
- 官方正式 curvature weight 為 `5e-4`。
- Bounds fix 穩定後，仍須測試 curvature 是否恢復為 `1e-4` 或官方 `5e-4`。
- `AMP=False` 與官方 base 相同。
- `torch.cuda.amp` 的 FutureWarning 僅為 API 棄用警告。

## 8.5 `projects\neuralangelo\model.py`：Ray / Sphere Bounds Fix

### NVIDIA 官方原始判定

```python
outside = dist_near.isnan()
```

### 目前修正

```python
outside = (
    (~torch.isfinite(dist_near))
    | (~torch.isfinite(dist_far))
    | (dist_far <= 0)
)
```

對 outside ray 使用官方原本已有的 dummy bounds：

```python
dist_near = 1.0
dist_far = 1.2
```

### 問題原因

道路相機可能位於單位球外。當相機朝道路前方拍攝時，全域球心可能位於相機後方。

此時 ray 可能：

1. 與球面有兩個實數交點。
2. 但兩個交點都位於相機後方。
3. `dist_near` 並非 NaN。
4. `dist_far <= 0`。
5. 官方判定因此未將該 ray 視為 outside。

負的 far distance 會使 background distances 反向，產生負 distance interval：

```text
alpha = 1 - exp(-density × interval)
```

當 interval 為負值時，指數項可能溢位，導致：

```text
巨大負值或 -Inf alpha
→ composite weights 出現 ±Inf
→ RGB 出現 NaN
→ render loss 與 total loss 出現 NaN
```

### 實際 Trace 結果

```text
iteration = 31
sample_idx = [230, 43]

background_alphas：
- 1 個 -Inf
- finite_min 約 -1.216e9

weights：
- 同時出現 +Inf 與 -Inf

RGB：
- 出現 NaN

render loss：
- NaN

total loss：
- NaN
```

Frame 230 的正規化 camera radius：

```text
約 1.0058
```

此值符合相機位於單位球外邊界的情況。

### 修正性質

- 這是目前唯一會直接改變特定 rays forward rendering 結果的 source-code 修正。
- 不改變可訓練參數。
- 不改變 checkpoint tensor shape。
- 有效的前向球面交點不受影響。
- 只處理：
  - 交點不存在
  - 交點為非有限值
  - 所有交點均位於相機後方
- 不需要翻轉 `transforms.json` 或全域座標軸。

# 最終判定

目前道路版本不是重新設計的 Neuralangelo 網路，而是：

1. 使用 NVIDIA 官方支援的真實 outdoor 場景設定。
2. 開啟官方已支援的 appearance embedding。
3. 調整訓練超參數與 Windows dataloader 設定。
4. 新增記錄、輸出與 non-finite 診斷工具。
5. 修正官方 ray / sphere 判定未處理 `dist_far <= 0` 的邊界情況。

在所有修改中，最需要獨立驗證的 source-code 行為變更是：

```text
dist_far <= 0 bounds fix
```

下一階段的最低驗證目標為：

```text
穩定通過 iteration 31
→ 完成至少 1,000 iterations
→ 保存可正常載入的 checkpoint
→ 再逐步恢復 curvature loss
```
